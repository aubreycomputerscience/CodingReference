LESSON 1: VARIABLES AND DATA TYPES

Lesson 1.1: Variables

If we have kittens, it is useful to give them names so we can call them by name and tell them apart. The same is true in computer science. In TypeScript, we create a variable by giving it a name and a value. Programmers call this declaring a variable. 

let hitPoints = 100;
let attackDamage = 30;
let incomingDamage = 10;

Here, hitPoints, attackDamage, and incomingDamage are variables: names that we have given to pieces of information so that we can use them later.

Now we can work with them just like we would work with variables in algebra. In fact, we call them variables. 

let remainingHitPoints = hitPoints - incomingDamage;

If we want to prevent a value from ever changing, we use const instead of let. Const stands for constant. 

const maxHP = 100; // This value cannot be changed.

Use const by default. Only use let if the value needs to change.

Lesson 1.2: Primitive Data Types

We can store different types of data in a variable or constant. 

const myHP = 100;
const myText = "some text";
const trueOrFalse = true;

The most basic types of information we can store are number, string (text), and boolean (true or false). We call these primitive data types.

If we want to be a little more explicit, we can also write: 

const myHP: number = 100; // Let there be no confusion: this is a number.
const myText: string = "some text";
const trueOrFalse: boolean = true;

Types are important because the type defines how something can be used. We cannot divide the number 3 by the word "cat" because it does not make sense. TypeScript can recognize many mistakes like this and warn us before the program runs. 

const hitPoints: number = "cat"; // Error: "cat" is not a number.

Later, we will also learn how to create our own types for information that TypeScript should treat differently.

The TypeScript programming language takes JavaScript and adds types, making it easier to build large applications and helping us avoid mistakes. When you have 20,000 lines of code, it is easy to do something that you should not. You do not want to discover that you have been pouring your breakfast cereal into the toaster.

Lesson 1.3: Collection Types

In TypeScript, we use collection types to store groups of information. Three important collection types are arrays, dictionaries, and sets.

ARRAY

An array is an ordered list of items.

const animals = ["cat", "dog", "monkey"];

DICTIONARY

A dictionary connects each key with a corresponding value. For example:

Oxford Dictionary

cat:
an animal that goes meow
dog:
an animal that goes woof

In TypeScript, we can create a dictionary using a Map: 

const animalDictionary = new Map([
    ["cat", "an animal that goes meow"],
    ["dog", "an animal that goes woof"]
]);

SET

A set stores a group of unique items. The same item cannot appear more than once. 

const animals = new Set(["cat", "dog", "monkey"]);

We can explicitly state what type of information a collection will contain: 

const animals: Array<string> = ["cat", "dog", "monkey"];

Read Array<string> as “an array of strings.”

Lesson 1.4: Union Types and Optional Values

So far, each variable has contained one type of information: 

let score: number = 100;
let playerName: string = "Alex";

Sometimes a variable may contain more than one possible type. We can describe this using a union type: 

let userID: string | number;

The vertical line means or. Read this as:

userID may contain a string or a number.

Both of these values are allowed:

userID = 4729;
userID = "user-4729";

A value with another type is not allowed:

userID = true; // Error

Before using a union value, we may need to check which type it currently contains: 

if (typeof userID === "string") {
    const message = "User ID: " + userID;
} else {
    const nextID = userID + 1;
}

Inside the first section, TypeScript knows that userID is a string. Inside the second section, it knows that userID is a number.

Optional Values

Sometimes a program may not have a valid value to store. For example, we may search for a customer but fail to find one.

A value that may or may not exist is called an optional value. In TypeScript, we can represent this by allowing the variable to contain either the expected type or undefined. 

let selectedCustomer: Customer | undefined;

If a customer is found, the variable contains a Customer. If no matching customer is found, it contains undefined. 

selectedCustomer = foundCustomer;
selectedCustomer = undefined;

The value undefined means that no valid value is currently available.

Before using selectedCustomer as a Customer, we must check that it is not undefined: 

if (selectedCustomer !== undefined) {
    // Use selectedCustomer.
}

This prevents us from trying to use information that was never found or does not exist.

Optional values are common when searching for information. For example, a function may return a character if one is found or undefined if no matching character exists: 

function findCharacter(name: string): Character | undefined {
    // Return the matching Character.
    // Return undefined if the character is not found.
}

Limiting the Allowed Values

A union type can also list the exact values that are allowed: 

type WindowState = "open" | "closed" | "minimized";

A variable using WindowState can contain only one of those three strings: 

let myWindowState: WindowState = "open";

myWindowState = "closed";    // Allowed
myWindowState = "minimized"; // Allowed
myWindowState = "hidden";    // Error

This is useful when managing the state of a program. Rather than allowing any string, we define the complete list of valid possibilities.

For example:

type GameState = "starting" | "playing" | "paused" | "finished";

let currentGameState: GameState = "starting";

TypeScript can now warn us if we accidentally use an invalid state: 

currentGameState = "done"; // Error

Union types allow us to describe both:

  • several possible types, such as string | number
  • several specific values, such as "open" | "closed" | "minimized"
