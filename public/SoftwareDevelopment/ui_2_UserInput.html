Chapter 2: User Input

A program can respond when the user clicks a button, enters text, presses a key, or drags something across the screen.

Lesson 2.1: Buttons and Text Input

Responding to a Button Click

A button has an onclick property that allows us to add code that will run when the button is clicked: 

const myButton = document.createElement("button");
myButton.textContent = "Click Me";

document.body.append(myButton);

myButton.onclick = () => {
    myButton.textContent = "You clicked me!";
};

The code inside the function runs when the user clicks the button.

Reading Text Input

An input field stores the text entered into it in its value property. We can read that value after the user clicks a button: 

const nameInput = document.createElement("input");
nameInput.type = "text";

const submitButton = document.createElement("button");
submitButton.textContent = "Submit";

document.body.append(nameInput, submitButton);

submitButton.onclick = () => {
    const userEnteredName = nameInput.value;
    // Do something with userEnteredName.
};

We can also run code whenever the text changes:

nameInput.oninput = () => {
    const currentText = nameInput.value;
};

Use onclick to respond to a click. Use oninput to respond whenever the value of an input changes.

Lesson 2.2: Keyboard Input

We can run code whenever the user presses a key. In this example, the arrow keys change a character’s position in a game, while the "q" key quits: 

document.addEventListener("keydown", (event) => {
    switch (event.key) {
        case "ArrowLeft":
            event.preventDefault();
            x = x - 10;
            break;

        case "ArrowRight":
            event.preventDefault();
            x = x + 10;
            break;

        case "ArrowUp":
            event.preventDefault();
            y = y - 10;
            break;

        case "ArrowDown":
            event.preventDefault();
            y = y + 10;
            break;

        case "q":
            quit();
            return;
    }

    updateUI();
    save();
});

Some common keys that you may use in an app include:

Key Value
Left arrow "ArrowLeft"
Right arrow "ArrowRight"
Up arrow "ArrowUp"
Down arrow "ArrowDown"
Enter "Enter"
Space bar " "
Q key "q"

Arrow keys normally scroll a webpage when there is room to scroll. The event.preventDefault() instruction prevents this normal response so that the arrow key controls the game instead.

Webpages also include a small margin around the page by default. Add the following code to the CSS file when building a full-screen app: 

body {
    /* Remove the space around the webpage or app. */
    margin: 0;
    padding: 0;
}

Lesson 2.3: Click Position

To find out where the user clicked, we can read information from the click: 

element.onclick = (event) => {
    const xPosition = event.clientX;     // Horizontal position
    const yPosition = event.clientY;     // Vertical position 
    const clickedElement = event.target;
};

For example, a drawing app could place a shape at the position of a click: 

myMainView.onclick = (event) => {
    addShape(event.clientX, event.clientY);
};

Lesson 2.4: Dragging an Element

To drag an element, we need to track when the user presses down, moves the pointer, and releases it. We also need to position the element using absolute coordinates. Otherwise, the webpage layout may determine its position independently of what we are tyring to do.

Create an Element to Move

const box = document.createElement("div");
box.style.width = "100px";
box.style.height = "100px";
box.style.background = "blue";
box.style.position = "absolute";

document.body.append(box);

Track Whether It Is Being Dragged

let isDragging = false;

Respond to Dragging

box.onpointerdown = () => {
    isDragging = true;
};

box.onpointermove = (event) => {
    if (isDragging === true) {
        box.style.left = event.clientX + "px";
        box.style.top = event.clientY + "px";
    }
};

box.onpointerup = () => {
    isDragging = false;
};

When the user presses down, isDragging becomes true. The box then follows the pointer until the user releases it. Pointer input works with a mouse, trackpad, touchscreen, or stylus.

Lesson 2.5: User Input and Events

So far, we have described how to respond to user input. We can now take a step back and look at what is happening more generally.

The browser watches for actions such as clicks, key presses, and pointer movement. These actions are called events. When an event occurs, the browser identifies where it happened and runs the code connected to it.

For example:

button.onclick = () => {
    // Respond to the click.
};

When the button is clicked, the browser recognizes the click, checks the button’s onclick property, and runs the code stored there.

Some events also provide additional information. A keyboard event tells us which key was pressed. A click or pointer event tells us where the action occurred.

Events are simply the system the browser uses to tell our program that the user did something.
