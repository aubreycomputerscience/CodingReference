Chapter 5: Functions

Lesson 5.1: What Is a Function?

As a program becomes larger, it becomes difficult to understand everything at once. We can make the program easier to work with by dividing it into smaller pieces of code called functions.

Each function should perform a small, clearly defined task. For example, a game might contain separate functions for calculating damage, healing a character, moving an enemy, and checking whether the player has won.

A function gives a name to a piece of code:

function healCharacter() {
    // Restore the character's health.
}

The name healCharacter tells us what the function does. In this way, a good function name acts like a topic sentence. It allows us to understand the purpose of the code without immediately reading every instruction inside it.

Creating a function is called defining a function. The code inside the function does not run until we call it: 

healCharacter();

The parentheses tell the program to run the function.

Functions help us:

  • divide a large program into smaller tasks
  • give meaningful names to sections of code
  • reuse code without writing it again
  • hide unnecessary details
  • make programs easier to read, test, and change

A function attached to an object or class is called a method. Functions and methods work in similar ways, but a method belongs to a particular object or class.

Lesson 5.2: Using Functions

Parameters and Arguments

A function can receive information through parameters.

function greetPerson(name: string) {
    const greeting = "Hello, " + name;
}

The parameter name is a variable that belongs to the function. It allows the function to work with different names.

When we call the function, we provide a value:

greetPerson("Maria");
greetPerson("Devon");

The value passed into a function is called an argument.

In this example:

function greetPerson(name: string) {
    const greeting = "Hello, " + name;
}

greetPerson("Maria");
  • name is the parameter.
  • "Maria" is the argument.

A function can have more than one parameter:

function calculateDamage(attack: number, defense: number) {
    const damage = attack - defense;
}

The arguments are matched with the parameters according to their position: 

calculateDamage(30, 10);

Here, 30 becomes attack and 10 becomes defense.

Clear parameter names make function calls easier to understand: 

const playerAttack = 30;
const enemyDefense = 10;

calculateDamage(playerAttack, enemyDefense);

This is often clearer than passing several unexplained numbers directly into the function.

Return Values

A function can send a result back to the code that called it. This is called a return value. 

function calculateDamage(attack: number, defense: number): number {
    return attack - defense;
}

The type after the parentheses states what kind of value the function returns: 

: number

We can store the returned value in a variable:

const damage = calculateDamage(30, 10);

The function receives 30 and 10, calculates the result, and returns 20. The value 20 is then stored in damage.

A returned value can also be used directly:

const remainingHitPoints =
    hitPoints - calculateDamage(attack, defense);

When a function reaches return, it immediately stops running: 

function calculateDamage(attack: number, defense: number): number {
    if (defense >= attack) {
        return 0;
    }

    return attack - defense;
}

If defense is greater than or equal to attack, the function returns 0 and skips the remaining code.

A function that does not return a value can use the return type void: 

function healCharacter(character: Character): void {
    character.heal();
}

TypeScript can usually determine the return type without our writing it. However, explicitly including it can make the purpose of a function clearer.

Optional Parameters and Values

Sometimes a parameter does not need to be provided. We can place a question mark after its name: 

function greetPerson(name: string, title?: string) {
    // Use name and title.
}

The function can now be called with or without a title:

greetPerson("Maria");
greetPerson("Maria", "Captain");

Inside the function, title may contain a string or it may contain undefined.

We can write this more explicitly using a union type: 

function greetPerson(name: string, title: string | undefined) {
    // Use name and title.
}

The vertical line means or. Read this as:

title can contain a string or undefined.

There is an important difference between these two forms. The question mark allows us to leave out the argument: 

greetPerson("Maria");

With string | undefined, the argument is still required, although its value may be undefined: 

greetPerson("Maria", undefined);

Union types can also describe other optional values:

function findCharacter(name: string): Character | undefined {
    // Return a Character if one is found.
    // Otherwise, return undefined.
}

The function may return a Character, or it may return undefined if no matching character exists.

Lesson 5.3: Scope

The part of a program where a variable can be used is called its scope.

A variable created inside a function belongs to that function:

function calculateDamage(attack: number, defense: number): number {
    const damage = attack - defense;

    return damage;
}

The variable damage can be used only inside calculateDamage(). 

const finalDamage = damage; // Error

Code outside the function cannot access it.

Parameters are also local variables. In this example, attack and defense exist only while the function is running: 

function calculateDamage(attack: number, defense: number): number {
    return attack - defense;
}

Different functions can use the same local variable names without interfering with one another: 

function calculateDamage(attack: number, defense: number): number {
    const result = attack - defense;

    return result;
}

function calculateHealing(currentHP: number, maxHP: number): number {
    const result = maxHP - currentHP;

    return result;
}

Each result belongs to its own function.

A variable created outside a function can usually be accessed from inside it: 

let score = 0;

function addPoint() {
    score = score + 1;
}

However, functions that change outside variables can become difficult to understand. We may need to search through the program to discover which functions can change score.

When possible, functions should receive the information they need through parameters and return a result: 

function addPoint(currentScore: number): number {
    return currentScore + 1;
}

score = addPoint(score);

Now the change to score is visible outside the function.

Lesson 5.4: Passing Primitive Values and Objects

Passing information into a function behaves differently depending on whether we pass a primitive value or an object.

Primitive Values

Numbers, strings, and Booleans behave like independent copies when passed into a function: 

function addHealth(hitPoints: number) {
    hitPoints = hitPoints + 10;
}

let heroHitPoints = 100;

addHealth(heroHitPoints);

After the function runs, heroHitPoints is still 100.

The parameter hitPoints received the value 100, but changing the parameter did not change the outside variable.

To change heroHitPoints, the function can return a new value: 

function addHealth(hitPoints: number): number {
    return hitPoints + 10;
}

let heroHitPoints = 100;

heroHitPoints = addHealth(heroHitPoints);

Now heroHitPoints contains 110.

Objects and References

Objects and arrays behave differently because variables access them through references. 

type Player = {
    name: string;
    hitPoints: number;
};

function takeDamage(player: Player) {
    player.hitPoints = player.hitPoints - 10;
}

const hero: Player = {
    name: "Alex",
    hitPoints: 100
};

takeDamage(hero);

After the function runs, hero.hitPoints contains 90.

When an object is passed into a function, the function receives another reference to the same object: 

hero ────────────────┐
                     ├──► { name: "Alex", hitPoints: 100 }
player parameter ────┘

Both hero and the parameter player lead to the same object. When the function changes player.hitPoints, it changes that shared object.

However, assigning a new object to the parameter does not make the outside variable refer to the new object: 

function replacePlayer(player: Player) {
    player = {
        name: "Sam",
        hitPoints: 200
    };
}

const hero: Player = {
    name: "Alex",
    hitPoints: 100
};

replacePlayer(hero);

The variable hero still refers to the original object: 

{
    name: "Alex",
    hitPoints: 100
}

The parameter received another reference to the original object. The function can use that reference to change the shared object, but it cannot make hero store a different reference.

Arrays behave in the same way:

function addAnimal(animals: Array<string>) {
    animals.push("monkey");
}

const myAnimals = ["cat", "dog"];

addAnimal(myAnimals);

// myAnimals now contains:
// ["cat", "dog", "monkey"]

The function and the outside variable both access the same array.

Lesson 5.5: Organizing Functions

A function name should clearly explain the task that the function performs.

Compare these names:

function doStuff() {
    // Perform several unclear tasks.
}
function calculateFinalScore() {
    // Calculate the player's final score.
}

The second name acts like a topic sentence. It tells us what the code is about before we read its details.

A function should usually perform one main task. If a function performs many unrelated tasks, it becomes difficult to name, understand, test, and change.

One useful pattern is to create a parent function that shows the major steps of a process: 

function completeBattle() {
    const attackDamage = calculateAttackDamage();
    const remainingHealth = applyDamage(attackDamage);

    showBattleResult(remainingHealth);
}

A reader can quickly understand the overall process:

  1. Calculate the damage.
  2. Apply the damage.
  3. Show the result.

The smaller functions contain the details:

function calculateAttackDamage(): number {
    // Calculate and return the damage.
}

function applyDamage(attackDamage: number): number {
    // Apply the damage and return the remaining health.
}

function showBattleResult(remainingHealth: number) {
    // Show the result to the player.
}

This creates two levels of detail. The parent function explains what happens, while the helper functions explain how each step works.

In general, it is easier to follow a program when helper functions do not lead through many additional layers of functions. We should be able to understand the main process without following a long chain of calls.

When possible, helper functions should receive the information they need and return a result rather than changing unrelated outside variables. 

let finalMessage = "";

function completeBattle() {
    const attackDamage = calculateAttackDamage();
    const remainingHealth = applyDamage(attackDamage);
    const message = createBattleMessage(remainingHealth);

    finalMessage = message;
}

The helper functions calculate and return values. The parent function controls the visible change to finalMessage.

This makes it easier to find where important values are changed.

Lesson 5.6: Mutating and Pure Functions

A mutating function changes an existing object or array: 

function healCharacter(character: Character) {
    character.hitPoints = character.maxHitPoints;
}

The function changes the Character object that was passed into it.

A pure function does not change outside values or objects. It uses its inputs to produce a result: 

function calculateHealing(hitPoints: number, maxHitPoints: number): number {
    return maxHitPoints - hitPoints;
}

Given the same inputs, a pure function produces the same result and does not change anything outside itself.

Pure functions are often easier to understand and test because we only need to look at their inputs and returned value.

For objects and arrays, a nonmutating function may create and return a new value: 

function addAnimal(animals: Array<string>, newAnimal: string): Array<string> {
    return [...animals, newAnimal];
}

const originalAnimals = ["cat", "dog"];
const newAnimals = addAnimal(originalAnimals, "monkey");

The original array remains unchanged:

originalAnimals: ["cat", "dog"]

newAnimals:      ["cat", "dog", "monkey"]

Creating new arrays and objects can require additional work. Mutation is not automatically wrong. The important question is whether the change is clear, controlled, and easy to find.

A useful general pattern is:

  • helper functions calculate and return values
  • a parent function controls important changes to the program

Lesson 5.7: Functions as Values

A function can be stored or passed into another function as a value.

First, we define a function:

function sayHello() {
    // Say hello.
}

Another function can receive it as a parameter:

function runTask(task: () => void) {
    task();
}

The type

() => void

means:

A function that receives no arguments and returns no value.

We pass the function without calling it:

runTask(sayHello);

Notice that we write sayHello, not sayHello(). 

runTask(sayHello);   // Pass the function.
runTask(sayHello()); // Call the function first.

Passing functions allows one part of a program to decide what task another part should perform.

TypeScript and JavaScript also allow us to create a function using arrow-function syntax: 

const sayHello = () => {
    // Say hello.
};

We can pass an arrow function directly:

runTask(() => {
    // Say hello.
});

Arrow functions are common in JavaScript code, especially when a short function is passed into another function. However, named functions are often easier for beginners to read and can make the purpose of the code clearer.
