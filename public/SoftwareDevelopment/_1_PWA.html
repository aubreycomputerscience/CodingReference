Chapter 1: Web Apps

In this course, we will build Progressive Web Apps, or PWAs. A PWA is a website designed to look and behave like an app. It runs in a browser, can work offline, and may be installed on a computer or mobile device.

We create the app using software on our computer, then publish it online. The app itself is made from text files containing our TypeScript, HTML, and CSS. When someone opens the app, the browser downloads those files and runs the code on their device. The app does not need to send information back and forth with a server in order to run.

TypeScript

TypeScript is the programming language we will use to write instructions for our apps. It is a modern version of JavaScript that adds tools intended to make programs easier to write and maintain.

JavaScript was originally created to add small programs and interactivity to webpages. Today, it is used to build complete applications. Browsers can read and run JavaScript directly. This is called interpreted code. We are providing instructions for the browser to read rather than creating machine code for the processor ourselves.

The most important feature TypeScript adds is type checking. TypeScript keeps track of the kinds of values used in a program and can warn us when we use them incorrectly.

For example, JavaScript may allow us to divide the number 3 by the word "cat" or try to access a property that does not exist. TypeScript can identify many mistakes like these before the program runs.

TypeScript also improves autocomplete. When the editor knows what kind of value we are working with, it can suggest the properties and functions available for that value.

Browsers do not read TypeScript directly. Before the browser receives the program, the TypeScript-specific information is removed, leaving regular JavaScript.

Vite

Our app is made from text files stored on our computer. The browser needs a way to access those files while we are working.

Vite starts a local development server. This server takes the files from our project and gives them to the browser, much like an online server would. This allows us to open the app in Chrome and test it before publishing it online.

Vite also handles our TypeScript files so the browser receives JavaScript it can run. As we make changes, Vite updates the app in the browser so we can quickly see the results.

Node.js and npm

You will often see the names Node.js and npm when working with Vite. Node.js is a program that allows your computer to read and run JavaScript without using a web browser.

This can be confusing because we are not using Node.js to run our app. The browser does that. We use Node.js to run Vite, and Vite runs a local development server that gives our app files to the browser.

npm stands for Node Package Manager. You can think of it as a tool for downloading programs and libraries used by a project. We can also use npm commands to start downloaded programs, such as Vite.

Thus, npm downloads Vite, Node.js runs Vite, and Vite gives our program files to the browser.

Web App Architecture

Web apps can be organized in different ways depending on what they need to do.

Static App

A static app works well for games, calculators, personal tools, reference apps, and many other projects.

The app consists of one or more files that run locally on the user’s device. If it needs to save information, it can store that data locally as well.

App
↓
Local Data

Most of the apps we build will begin with this structure.

App with an Online Database

Suppose we want a user to sign in on a school computer, save information, and then access the same information later from home. Storing the data only on one device would not work.

Instead, the app can connect to an online database service.

App
↓
Online Database

This allows information to be shared between devices and users. It also introduces additional concerns, including authentication, permissions, data validation, session management, and error handling.

App with a Backend

Some apps rely on programs running on a company’s servers. This allows the company to manage the system itself, run more complicated processes, and control work that should not be trusted to a user’s device.

For example, a banking app should not allow code running on a phone to decide what the user’s bank balance should be. The app sends a request to the bank’s computers, which identify the user, check the request, update the account, and return the result.
