LESSON 8: OBJECT LITERALS

Lesson 8.1: Grouping Related Data

Sometimes several pieces of information belong together. For example, a game player may have a name, hit points, and a score.

We could store each value in a separate variable:

const playerName = "Alex";
let playerHitPoints = 100;
let playerScore = 500;

However, these variables all describe the same player. It is often clearer to group them together in one value.

In JavaScript and TypeScript, we can do this using an object literal: 

const player = {
    name: "Alex",
    hitPoints: 100,
    score: 500
};

An object literal is a collection of related values grouped under one name.

Each named value inside the object is called a property.

In this example:

Object: player

Property: name
Value:    "Alex"

Property: hitPoints
Value:    100

Property: score
Value:    500

The braces mark the beginning and end of the object. Each property contains a name followed by a colon and its value. 

const player = {
    name: "Alex",
    hitPoints: 100
};

The property names are name and hitPoints. Their corresponding values are "Alex" and 100.

Object literals are useful for simple grouped data such as:

  • a player’s name, health, and score
  • a product’s name and price
  • a location’s horizontal and vertical position
  • a user’s account information

Lesson 8.2: Using Object Literals

We use a period to access a property:

const playerName = player.name;
const currentHitPoints = player.hitPoints;

Read player.name as:

The name property belonging to player.

We can also change a property:

player.hitPoints = 80;

The player object now contains:

name:      "Alex"
hitPoints: 80
score:     500

Even though player was declared using const, its properties can still change. 

const player = {
    name: "Alex",
    hitPoints: 100
};

player.hitPoints = 80; // Allowed

The constant player must continue to refer to the same object. However, the information stored inside that object may change.

We cannot make player refer to a different object:

player = {
    name: "Maria",
    hitPoints: 100
}; // Error

This is the same reference behavior that we saw with arrays.

Lesson 8.3: Object Literals and References

Object literals are accessed through references.

Consider the following code:

const firstPlayer = {
    name: "Alex",
    hitPoints: 100
};

const secondPlayer = firstPlayer;

This does not create a second player object. It gives us a second variable containing a reference to the same object. 

firstPlayer  \
              >  Same object: { name: "Alex", hitPoints: 100 }
secondPlayer /

Changing the object using either variable changes the shared object: 

secondPlayer.hitPoints = 50;

// firstPlayer.hitPoints is now 50.
// secondPlayer.hitPoints is also 50.

Both variables lead to the same information.

If we want to create a separate object containing the same properties, we can use the spread operator: 

const firstPlayer = {
    name: "Alex",
    hitPoints: 100
};

const copiedPlayer = {
    ...firstPlayer
};

Read ...firstPlayer as:

Take all the properties from firstPlayer and place them here.

Now the two variables refer to separate objects:

copiedPlayer.hitPoints = 50;

// firstPlayer.hitPoints is still 100.
// copiedPlayer.hitPoints is now 50.

As with arrays, this creates a shallow copy. If one of the properties contains another object or array, that inner value is still accessed through a shared reference.

Lesson 8.4: Passing an Object into a Function

We can pass an object literal into a function:

function healPlayer(player: { name: string; hitPoints: number }) {
    player.hitPoints = 100;
}

The information between the braces describes the properties that the function expects.

The function requires an object containing:

  • a name property whose value is a string
  • a hitPoints property whose value is a number

We can pass in a matching object:

const hero = {
    name: "Alex",
    hitPoints: 50
};

healPlayer(hero);

After the function runs, hero.hitPoints contains 100.

The function receives another reference to the same object. Therefore, changing the object through the parameter also changes the object accessed through hero.

Writing the complete property description inside every function can become repetitive: 

function healPlayer(player: { name: string; hitPoints: number }) {
    player.hitPoints = 100;
}

function damagePlayer(player: { name: string; hitPoints: number }) {
    player.hitPoints = player.hitPoints - 10;
}

We can give this shape a name using a type alias.

Lesson 8.5: Describing the Shape

A type alias describes the properties an object must contain: 

type Player = {
    name: string;
    hitPoints: number;
    score: number;
};

This does not create a player object. It only describes what a value must look like to be used as a Player.

We can then create an object literal with that shape:

const player: Player = {
    name: "Alex",
    hitPoints: 100,
    score: 500
};

The object literal creates the actual grouped data. The type alias describes the shape that the data must have.

TypeScript checks that the required properties are present and contain the correct types. 

const player: Player = {
    name: "Alex",
    hitPoints: 100
}; // Error: score is missing.

It also checks the type of each property:

const player: Player = {
    name: "Alex",
    hitPoints: "healthy",
    score: 500
}; // Error: hitPoints must be a number.

Once the shape has a name, we can reuse it in functions:

function healPlayer(player: Player) {
    player.hitPoints = 100;
}

function damagePlayer(player: Player, damage: number) {
    player.hitPoints = player.hitPoints - damage;
}

This makes the function declarations shorter and ensures that they use the same description of a player.
