Lesson 3.2: Modules

Dividing Code into Files

We divide an application into separate files because smaller files make the code easier to read and understand. Once a file grows to over 1,000 lines of code, it starts to become difficult to work with. Dividing the code into separate files is similar to dividing a book into chapters.

Furthermore, it allows us to hide the nitty-gritty details. Think about building a house. The person coordinating the project does not need to know every detail of how each job is completed. They can ask the electrician to wire a room or ask the plumber to install a sink. The electrician handles the electrical system, while the plumber handles the plumbing.

In a similar manner, we can divide our codebase into sections that perform specialized tasks. Everything related to a task can be put in the same file, helping us organize our projects, hide messy details, and reuse code.

Creating a File

A module is just a text file in which we store code. To create a new file, select File → New File and give it a name ending with .ts. 

myLogic.ts

Then you can start coding. To make a variable or function available for other modules to use, write the word export in front of it. 

export const startingScore = 0;

export function add(firstNumber: number, secondNumber: number): number {
    return firstNumber + secondNumber;
}

A file containing a top-level import or export is treated as a module. Alternatively, if you do not have anything you wish to make available, write export {}; at the top of the file.

Importing a Module

To use our code in another module, we need to import it. 

import * as myLogic from "./myLogic.ts";

Now we can access myLogic.startingScore and myLogic.add().

When JavaScript imports a module for the first time, it runs any free-floating code that is not inside a class or function. Because this may result in unexpected behavior, this practice should be avoided. A module should be like a library of functions or classes that you can use, not code that runs automatically.
