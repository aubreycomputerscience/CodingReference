Chapter 2: Sorting Algorithms

Lesson 2.1: Bubble Sort

Bubble sort moves through a list from left to right, comparing neighboring values. If two values are in the wrong order, it swaps them.

Suppose we begin with:

5, 2, 4, 1

We first compare 5 and 2. Since 5 is larger, we swap them: 

2, 5, 4, 1

Next, we compare 5 and 4:

2, 4, 5, 1

Then we compare 5 and 1:

2, 4, 1, 5

After one complete pass, the largest value has moved one step at a time until it reaches the far right. We then begin another pass and move the next-largest value into position. We repeat this process until the entire list is sorted.

If the list contains n items, bubble sort makes roughly one pass for each item. During each pass, it moves through most of the list. As the list grows, the amount of work grows very quickly.

Bubble sort is easy to visualize and commonly appears in introductory computer science courses. However, it performs far too much work for most real programs.

Lesson 2.2: Selection Sort

Selection sort repeatedly searches the unsorted values for the smallest item.

Suppose we begin with:

5, 2, 4, 1

The easiest way to understand selection sort is to imagine creating a new list. We search the original list and find the smallest value, 1, then add it to the new list: 

Sorted list: 1
Remaining values: 5, 2, 4

We search again and find 2:

Sorted list: 1, 2
Remaining values: 5, 4

We continue until the new list is complete:

Sorted list: 1, 2, 4, 5

The main idea is simple: repeatedly find the smallest remaining item and place it at the end of the sorted list.

Creating a second list requires additional memory. We can avoid this by rearranging the original list instead.

We begin again with:

5, 2, 4, 1

We find the smallest value, 1, and swap it with the value in the first position: 

1, 2, 4, 5

The first position is now complete. We leave it alone and search the remaining values for the next-smallest item. We continue moving from left to right until every position is complete.

Selection sort always performs roughly the same amount of work. Even if the list is already sorted, it still searches through all of the remaining values to confirm which one is smallest.

Lesson 2.3: Insertion Sort

Insertion sort works much like arranging playing cards in your hand. We create a new list of sorted items and add the original values one at a time.

Suppose the original values are:

5, 2, 4, 1

We take the first item, 5, and place it in the sorted list: 

Sorted list: 5

Next, we take 2. We begin at the right side of the sorted list and move left until we find where 2 belongs. Since 2 is smaller than 5, we place it before 5: 

Sorted list: 2, 5

Next, we take 4. We again begin on the right and check each item while moving left. Since 4 is smaller than 5 but larger than 2, we place it between them: 

Sorted list: 2, 4, 5

Finally, we take the next item, 1. We check the sorted values from right to left until we reach the beginning, then place 1 there: 

Sorted list: 1, 2, 4, 5

Insertion sort builds the sorted list one item at a time. For each new item, it begins at the right side of the sorted values and moves left until it finds the correct position.

We can implement insertion sort using a second array, which makes the idea easy to understand. We can also rearrange the original array by shifting values to the right until there is room for the new item. This saves memory.

Insertion sort can stop searching as soon as it finds the correct position. If the list is already sorted or nearly sorted, it requires very little work.

It also has very little overhead. For this reason, more advanced sorting algorithms often switch to insertion sort when they reach a small group of items. The larger algorithm divides the problem, and insertion sort quickly finishes the small sections.

Lesson 2.4: What Makes a Sort Good?

Now that we have seen several ways to sort a list, we can compare them more carefully.

A sorting algorithm is not judged only by whether it produces the correct order. We should also consider how quickly it runs, how much additional memory it requires, and whether it preserves the order of items that have the same sorting value.

Speed

Bubble sort, selection sort, and insertion sort become slow when the list grows because they repeatedly move through large portions of the data.

More advanced algorithms, such as merge sort and quicksort, divide the problem into smaller sections. This allows them to handle very large lists much more efficiently.

The difference may not matter when sorting ten items. It matters enormously when sorting millions of items.

Memory

Some sorting algorithms rearrange the values inside the original array. These are called in-place sorts. They require very little additional memory.

Other algorithms create temporary arrays while they work. This can make the algorithm easier to understand or implement, but it requires more memory.

Historically, computers had very little memory, so rearranging values inside the original array was especially important. Modern computers have far more memory, but memory still matters when sorting very large amounts of information.

Stable Sorting

A stable sort preserves the original order of items that have the same sorting value.

Suppose our contacts contain two people with the same name:

Bill Gates, Seattle
Bill Gates, Santa Barbara

If we sort by name, both records have the same sorting value. A stable sort keeps them in the same order in which they originally appeared.

An unstable sort may reverse them:

Bill Gates, Santa Barbara
Bill Gates, Seattle

The information is still technically sorted by name, but the records may unexpectedly change places whenever the list is sorted. This creates a confusing user experience.

Stability does not matter when duplicate values are completely identical. If we are sorting the numbers 3, 3, 3, there is no meaningful difference between one 3 and another. Stability becomes important when we sort records using only part of the information they contain.

Lesson 2.5: Merge Sort

Merge sort divides the list into smaller sections and then combines those sections in sorted order.

Suppose we begin with eight values:

7, 3, 6, 2, 8, 1, 5, 4

Merge sort repeatedly divides the list in half until each section contains one item: 

[7, 3, 6, 2]    [8, 1, 5, 4]

[7, 3]    [6, 2]    [8, 1]    [5, 4]

[7]    [3]    [6]    [2]    [8]    [1]    [5]    [4]

A group containing one item is already sorted. Merge sort then combines the items into sorted groups of two: 

[3, 7]    [2, 6]    [1, 8]    [4, 5]

It combines those groups into sorted groups of four:

[2, 3, 6, 7]    [1, 4, 5, 8]

Finally, it combines the two halves:

[1, 2, 3, 4, 5, 6, 7, 8]

Turn-Taking Sort

When merge sort combines two sorted groups, it does not need to sort the combined group from the beginning.

Suppose we have:

Left group:  [2, 3, 6, 7]
Right group: [1, 4, 5, 8]

We compare the next available number from each group. Since 1 is smaller than 2, we take 1 from the right group: 

Sorted values: [1]

The next available numbers are now 2 and 4. Since 2 is smaller, we take 2 from the left group: 

Sorted values: [1, 2]

The next available numbers are 3 and 4, so we take 3: 

Sorted values: [1, 2, 3]

We continue taking the smaller of the next two available numbers until both groups are empty: 

Sorted values: [1, 2, 3, 4, 5, 6, 7, 8]

In this course, we will call this a turn-taking sort. More formally, the process is called merging.

Merge sort divides the list into about log n levels. At each level, it processes all n items. Its complexity is therefore O(n log n).

Merge sort always provides O(n log n) performance and is stable. Its main disadvantage is memory. A typical merge sort creates temporary arrays while dividing and combining the data.

Lesson 2.6: Quicksort or Pivot Sort

Quicksort divides the list using a value called a pivot.

Suppose we begin with:

7, 3, 6, 2, 8, 1, 5, 4

We choose 5 as the pivot. Values smaller than 5 go on one side, while values larger than 5 go on the other: 

Smaller: [3, 2, 1, 4]
Pivot: 5
Larger: [7, 6, 8]

We repeat the same process within the smaller and larger groups until the entire list is sorted.

Quicksort performs well when each pivot divides the values into two reasonably even groups. In this case, it provides approximately O(n log n) performance.

However, the pivot may divide the data poorly. Suppose the list is already sorted and we always choose the first value as the pivot: 

1, 2, 3, 4, 5, 6, 7, 8

The pivot 1 leaves one empty group and one group containing nearly every remaining value. If this happens repeatedly, quicksort falls to O(n²).

Randomized quicksort avoids this predictable problem by shuffling the values before sorting or choosing pivots randomly. Other variations examine several values and select a pivot that is more likely to divide the list evenly.

Duplicate values create another problem for a simple quicksort. If the list contains many copies of the pivot, a basic two-group implementation may divide the data poorly. A three-way quicksort creates separate groups for values smaller than, equal to, and larger than the pivot. This handles duplicate values much more efficiently.

Traditional textbook quicksort rearranges values inside the original array and is not stable. Equal records may change order during the swaps.

Quicksort is often extremely fast and uses less additional memory than a typical merge sort. However, its performance depends on how well the pivots divide the data.

Lesson 2.7: Comparing Sorting Algorithms

Algorithm Best Case Average Case Worst Case Additional Memory Stable
Bubble SortO(n²)O(n²)O(n²)LowYes
Selection SortO(n²)O(n²)O(n²)LowNo
Insertion SortO(n)O(n²)O(n²)LowYes
Merge SortO(n log n)O(n log n)O(n log n)HigherYes
QuicksortO(n log n)O(n log n)O(n²)LowNo

Bubble sort is easy to understand but performs too much unnecessary work for most real programs.

Selection sort makes fewer swaps than bubble sort, but it still searches through all of the remaining values during every round.

Insertion sort is useful for small or nearly sorted lists. Its low overhead also makes it useful as part of a larger sorting algorithm.

Merge sort provides reliable O(n log n) performance and preserves the order of equal items. However, it normally requires additional memory.

Quicksort is often extremely fast and uses little additional memory, but poor pivots can produce O(n²) performance. Traditional quicksort is also not stable.

No sorting algorithm is best in every situation. The right choice depends on the amount of data, the arrangement of the data, the available memory, and whether stability matters.

Lesson 2.8: Implementing Merge Sort

The main merge sort function divides the list into halves. The turnTakingSort() function combines two sorted lists into one sorted list. 

function mergeSort(numbers: Array<number>): Array<number> {

    if (numbers.length <= 1) {
        return numbers;
    }

    const middleIndex = Math.floor(numbers.length / 2);

    const leftHalf = numbers.slice(0, middleIndex);
    const rightHalf = numbers.slice(middleIndex);

    const sortedLeftHalf = mergeSort(leftHalf);
    const sortedRightHalf = mergeSort(rightHalf);

    return turnTakingSort(sortedLeftHalf, sortedRightHalf);
}

function turnTakingSort(leftNumbers: Array<number>, rightNumbers: Array<number>): Array<number> {

    const sortedNumbers: Array<number> = [];

    let leftIndex = 0;
    let rightIndex = 0;

    while (leftIndex < leftNumbers.length && rightIndex < rightNumbers.length) {
        const leftNumber = leftNumbers[leftIndex];
        const rightNumber = rightNumbers[rightIndex];

        if (leftNumber <= rightNumber) {
            sortedNumbers.push(leftNumber);
            leftIndex = leftIndex + 1;
        } else {
            sortedNumbers.push(rightNumber);
            rightIndex = rightIndex + 1;
        }
    }

    while (leftIndex < leftNumbers.length) {
        sortedNumbers.push(leftNumbers[leftIndex]);
        leftIndex = leftIndex + 1;
    }

    while (rightIndex < rightNumbers.length) {
        sortedNumbers.push(rightNumbers[rightIndex]);
        rightIndex = rightIndex + 1;
    }

    return sortedNumbers;
}

The comparison uses <= rather than <. If the two values are equal, the value from the left group is added first. This preserves the original order and keeps the sort stable.

Lesson 2.9: Implementing Pivot Sort

The following implementation uses three groups so that it can handle duplicate values clearly. It is easier to read than a traditional in-place quicksort, but it creates additional arrays. 

function pivotSort(numbers: Array<number>): Array<number> {

    if (numbers.length <= 1) {
        return numbers;
    }

    const pivotIndex = Math.floor(numbers.length / 2);
    const pivot = numbers[pivotIndex];

    const smallerNumbers: Array<number> = [];
    const equalNumbers: Array<number> = [];
    const largerNumbers: Array<number> = [];

    for (const number of numbers) {
        if (number < pivot) {
            smallerNumbers.push(number);
        } else if (number > pivot) {
            largerNumbers.push(number);
        } else {
            equalNumbers.push(number);
        }
    }

    const sortedSmallerNumbers = pivotSort(smallerNumbers);
    const sortedLargerNumbers = pivotSort(largerNumbers);

    return [
        ...sortedSmallerNumbers, // Add every value from the smaller array.
        ...equalNumbers,         // Add every value equal to the pivot.
        ...sortedLargerNumbers   // Add every value from the larger array.
    ];
}

This version chooses the middle item as the pivot and places values equal to the pivot into their own group. This prevents duplicate values from repeatedly passing through the recursive calls.

Unlike traditional quicksort, this implementation creates several new arrays. It is designed to make the algorithm easy to understand rather than to minimize memory use.
