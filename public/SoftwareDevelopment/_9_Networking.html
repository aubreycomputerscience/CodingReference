Chapter 8: Loading Data from Files and the Internet

Applications often use information stored outside their TypeScript files. An app might display an image, insert instructions from an HTML file, load a list of characters from a data file, or request current information from an online service.

Loading a file that belongs to our app is different from requesting information from another server. Our own files are included with the project and remain under our control. Information requested from another server may be unavailable, blocked, changed, or require permission.

Lesson 8.1: Loading Images and HTML

HTML can load and display certain kinds of files directly. An image element uses src to identify the image that should appear on the page: 

<img src="images/superhero.png">

A link uses href to open another webpage or file when the user selects it: 

<a href="instructions.html">View Instructions</a>

The link does not insert the instructions into the current page. It opens the linked page instead.

Displaying Another Page with an iframe

An iframe displays one webpage inside another webpage: 

<iframe src="instructions.html"></iframe>

The page inside the iframe remains a separate webpage. This can be useful for embedding a map, video, form, document, or another page that should remain independent from the rest of the app. Some websites allow their pages to be embedded, while others deliberately block it. An iframe is therefore different from loading HTML and adding those elements directly to our page.

Inserting HTML into the Current Page

When we want the loaded HTML to become part of the current page, we can retrieve the HTML file and insert it into an element: 

const content = document.getElementById("content")!;

async function loadInstructions(): Promise<void> {
    // We created a file named instructions.html containing HTML text.
    const response = await fetch("instructions.html"); // Retrieve the file.
    const html = await response.text(); // Get the HTML text from the response.

    content.innerHTML = html; // Insert the HTML inside the content element.
}

Setting content.innerHTML replaces the existing contents of the selected element with the loaded HTML. We could instead replace the contents of the entire page by assigning the HTML to document.body.innerHTML, but we will normally use a particular content element so that the rest of the interface remains in place.

Only insert HTML that belongs to the app or comes from another source that you trust. Text entered by a user should normally be displayed with textContent so that it is treated as text rather than interpreted as HTML. This helps prevent someone from inserting unwanted or harmful HTML or JavaScript into the page.

Lesson 8.2: Understanding JSON

Programs often need to save or transfer structured data. A text file can contain this information using a format called JSON, or JavaScript Object Notation.

JSON represents data using values, arrays, and collections of key-value pairs. Although its name comes from JavaScript, JSON is used by many programming languages and online services.

Simple Values

JSON can contain strings, numbers, Boolean values, and null: 

"Super Cat"
42
true
null

Arrays

An array is an ordered list of values surrounded by square brackets: 

[
    "flight",
    "super strength",
    "night vision"
]

The values in an array may also be numbers, Boolean values, or more complicated data.

Key-Value Data

Braces contain a collection of keys and values:

{
    "name": "Super Cat",
    "powerLevel": 90,
    "isHero": true
}

Each key identifies a value. In most programming languages, this kind of structure would be described as a dictionary, map, or key-value collection.

When TypeScript reads this JSON, JavaScript represents the key-value collection as an object. We can therefore access the values using ordinary property names: 

hero.name
hero.powerLevel
hero.isHero

The JSON file itself is still text. It does not contain a TypeScript class or a functioning object. JavaScript creates the object when the JSON text is converted into data the program can use.

Arrays of Key-Value Data

JSON structures can be combined. The following array contains three superheroes: 

[
    {
        "name": "Super Cat",
        "powerLevel": 90
    },
    {
        "name": "The Falcon",
        "powerLevel": 75
    },
    {
        "name": "Captain Turtle",
        "powerLevel": 60
    }
]

Each item in the array is a separate collection of key-value pairs.

Nested Data

Values can themselves contain arrays or additional collections of key-value pairs: 

{
    "teamName": "The Night Watch",
    "headquarters": {
        "city": "Dallas",
        "isSecret": true
    },
    "members": [
        {
            "name": "Super Cat",
            "abilities": [
                "night vision",
                "super hearing"
            ]
        },
        {
            "name": "The Falcon",
            "abilities": [
                "flight",
                "long-distance vision"
            ]
        }
    ]
}

The outer collection describes the team. The value stored for "headquarters" is another key-value collection. The value stored for "members" is an array, and each member contains an additional array of abilities.

JSON uses a small number of rules consistently. Keys and strings must use double quotation marks. JSON does not allow comments, functions, undefined, type declarations, or trailing commas.

Lesson 8.3: Loading Data from a JSON File

Suppose we save the following data in a file named superheroes.json: 

[
    {
        "name": "Super Cat",
        "powerLevel": 90,
        "abilities": [
            "night vision",
            "super hearing"
        ]
    },
    {
        "name": "The Falcon",
        "powerLevel": 75,
        "abilities": [
            "flight",
            "long-distance vision"
        ]
    }
]

In a Vite project, place a file that the running app needs to load inside the public folder: 

public/superheroes.json

When we retrieve this file, the browser initially receives its contents as text. That text must then be converted into arrays and key-value data that the program can use. JavaScript represents the JSON arrays as arrays and the JSON key-value collections as objects.

We can describe the expected shape of each superhero with a TypeScript type: 

type Superhero = {
    name: string;
    powerLevel: number;
    abilities: string[];
};

We can then load the file:

async function loadSuperheroes(): Promise<void> {
    const response = await fetch("superheroes.json");
    const superheroes = await response.json() as Superhero[];

    displaySuperheroes(superheroes);
}

fetch() retrieves the file and returns a Response. Calling response.json() reads the JSON text and converts it into JavaScript data. Because the outermost JSON value is an array, the result is an array of superhero objects.

The following part tells TypeScript what kind of result we expect: 

as Superhero[]

This does not inspect or validate the downloaded data. It only tells TypeScript to treat the result as an array of Superhero values. Because this file belongs to our own app, we can make sure that its contents match the type.

Lesson 8.4: When Loading Data Fails

Even a file that belongs to our app may fail to load. The file could be missing, its name could be misspelled, the device could lose its connection, or the JSON could be incorrectly formatted. 

async function loadSuperheroes(): Promise<void> {
    try {
        const response = await fetch("superheroes.json");

        if (!response.ok) {
            // The server responded, but it could not provide the file.
            errorLabel.textContent = "The superhero file could not be found.";
            return;
        }

        const superheroes = await response.json() as Superhero[];
        displaySuperheroes(superheroes);
    } catch {
        // Something prevented the request or JSON conversion from completing.
        errorLabel.textContent = "The superhero data could not be loaded.";
    }
}

The try section contains code that may fail. If one of those operations produces an error, JavaScript stops running the remaining statements inside try and moves to catch. The catch section allows us to display an error message or take some other action instead of allowing the failure to continue through the program.

Not every unsuccessful request produces this kind of error. Sometimes the server responds normally but reports that it could not provide what we requested. A missing file commonly produces a response code called 404, which means that the requested file was not found. Because the server still returned a response, fetch() completes and gives us a Response object. We check response.ok to determine whether that response reports success.

Other failures can move directly to catch. For example, the device may lose its connection, the server may be unreachable, or response.json() may be unable to convert incorrectly formatted JSON. The catch section does not repair the problem, but it allows the app to respond without continuing as though valid data had been loaded.

The try and catch are not required in order to use fetch(). They are added when we want the program to handle a failure instead of allowing the async function to fail without displaying a useful message.

Lesson 8.5: Requesting Data from an Online Service

The fetch() function retrieves data from a web address. That address might point to a file included with our own app: 

const response = await fetch("superheroes.json");

It can also point to a file or service hosted somewhere else on the internet: 

const response = await fetch(
    "https://example.com/superheroes.json"
);

The basic process is the same. fetch() retrieves the information, and response.json() converts the returned JSON text into arrays and objects that our program can use.

The important difference is that we control files included with our own app. When we request information from another server, that server may be unavailable, change its data, restrict access, or require permission.

A service that provides information for other programs is commonly called an API, or application programming interface. Instead of returning a webpage designed for a person to read, an API commonly returns JSON designed for another program to process.

We could retrieve superhero data from an online JSON file using the same type and nearly the same code: 

type Superhero = {
    name: string;
    powerLevel: number;
    abilities: string[];
};

async function loadOnlineSuperheroes(): Promise<void> {
    const url =
        "https://example.com/data/superheroes.json";

    const response = await fetch(url);
    const superheroes =
        await response.json() as Superhero[];

    displaySuperheroes(superheroes);
}

The only important change is the address passed to fetch(). A relative address such as "superheroes.json" points to a file included with our app. A complete address beginning with https:// points to another location online.

Requesting Weather Data

Some APIs allow us to provide additional information as part of the web address. Open-Meteo, for example, needs to know the location and which weather measurements we want. 

type WeatherData = {
    current: {
        // These property names are chosen by Open-Meteo.
        // Using the same names lets us read the returned data directly.
        temperature_2m: number;
        wind_speed_10m: number;
    };
};

async function loadWeather(): Promise<void> {
    // Add parameters to the web address to describe our request.
    const apiURL =
        "https://api.open-meteo.com/v1/forecast" +
        "?latitude=33.68" +
        "&longitude=-117.87" +
        "&current=temperature_2m,wind_speed_10m" +
        "&temperature_unit=fahrenheit" +
        "&wind_speed_unit=mph";

    const response = await fetch(apiURL);
    const weather =
        await response.json() as WeatherData;

    temperatureLabel.textContent =
        `${weather.current.temperature_2m}°F`;

    windLabel.textContent =
        `${weather.current.wind_speed_10m} mph`;
}

The unusual property names such as temperature_2m and wind_speed_10m come from Open-Meteo. Our TypeScript type uses those same names so that they match the keys in the returned JSON.

The first part of the address identifies the API:

https://api.open-meteo.com/v1/forecast

The additional text describes the information we want. This is somewhat like passing arguments to a function. A function uses formal parameters, while a web request can place query parameters after a question mark in the address: 

?latitude=33.68

An ampersand separates each additional parameter:

&longitude=-117.87
&current=temperature_2m,wind_speed_10m
&temperature_unit=fahrenheit

Each parameter contains a name and a value. For example: 

latitude=33.68

tells the server that the value for latitude is 33.68.

The server reads these parameters, prepares the requested weather information, and returns JSON. The returned JSON may contain more information than our program needs. The WeatherData type describes only the part that we intend to use.

Because an outside server introduces additional uncertainty, we should also handle possible failures: 

async function loadWeather(): Promise<void> {
    try {
        const response = await fetch(apiURL);

        if (!response.ok) {
            errorLabel.textContent =
                "The server could not complete the request.";
            return;
        }

        const weather =
            await response.json() as WeatherData;

        displayWeather(weather);
    } catch {
        errorLabel.textContent =
            "The weather data could not be loaded.";
    }
}

This uses the same error handling introduced for our own JSON file. The difference is that we do not control the outside server, so changes, outages, blocked requests, or unexpected data are more likely.

Lesson 8.6: Why We Cannot Read Every Webpage

A program generally cannot download and examine the contents of an arbitrary webpage. Browsers restrict requests between unrelated websites, and the other server must allow our app to read its response. This system is called Cross-Origin Resource Sharing, or CORS.

Even when a request is allowed, an ordinary webpage usually returns HTML designed to be displayed by a browser rather than clean data designed for another program. The page may also require a login, change its structure, limit automated requests, or prohibit another application from using its content.

For these reasons, applications normally request online information through an API or a data file created for that purpose rather than attempting to extract information from an ordinary webpage.

Lesson 8.7: Real-World Networking

The examples in this lesson are fairly simple because our own files and Open-Meteo do not require user accounts or secret credentials. Other online services may require authentication, special request headers, usage limits, payment, or additional setup.

Some services require an API key that identifies the application making the request. A permanent secret key cannot be safely hidden inside browser code because users can inspect the files sent to their browser. Applications that require a protected secret commonly send the request through a backend server or use a service designed to accept restricted browser credentials.

Larger services such as Firebase or AWS often provide their own TypeScript libraries. These libraries still communicate over a network, but they handle many request details for us.

Lesson 8.8: Sending JSON

Earlier, we used:

const data = await response.json();

This receives JSON from a file or server and converts it into JavaScript arrays and objects.

When sending data in the other direction, we normally begin with a TypeScript or JavaScript object: 

const user = {
    name: "Jon Snow",
    score: 12
};

Before the data can be sent to a server or saved as JSON, we convert the object into JSON text: 

const jsonText = JSON.stringify(user);

The resulting text is:

{"name":"Jon Snow","score":12}

The two directions are therefore:

const data = await response.json(); // JSON text → program data
const jsonText = JSON.stringify(data); // program data → JSON text

Converting program data into text that can be saved or transmitted is called serialization. Converting received JSON into values the program can use is called deserialization.
