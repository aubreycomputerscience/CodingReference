Chapter 2: Getting Started

We will use Visual Studio Code, usually called VS Code, to create and edit our projects. We will also use the terminal inside VS Code to run the program that prepares our TypeScript code and sends the app to the browser.

VS Code is a complicated program with many features. Ignore anything that you have not been asked to use. You need only a few parts of the interface.

Lesson 18.1: Working in VS Code

The File Explorer

Use the File Explorer in the left sidebar to open the files in your project. It is the top icon in the sidebar. If you are working on a small screen, close the sidebar when you do not need it so that you have more room for your code. Your project contains many files, but you should ignore files that you are not currently using.

When starting, we will mostly work with:

  • myCode.ts
  • myLogic.ts
  • myUIElements.ts
  • style.css

More generally:

Location Purpose
src folder TypeScript code. src stands for source.
public folder Images, additional HTML pages, the app manifest, and other files copied directly into the finished app
index.html The starting HTML page
style.css CSS styling
package.json Project settings and commands

The Bottom Panel

Use the bottom panel to see coding errors or run the development server that sends your app to the browser. Open the terminal by selecting: 

View → Terminal

To see a list of coding errors, select:

View → Problems

The Problems tab shows errors found while checking your code. Errors that occur while the app is running may instead appear in the browser.

The Terminal allows us to type commands that prepare, run, or build the project. You can switch between Problems and Terminal using the tabs at the top of the bottom panel.

If the preview becomes stuck or you need to restart the development server, click the trash button at the top of the bottom panel. You can then open a new terminal and run the command again.

Class Rules

Unless your teacher tells you otherwise:

  1. Do not use the AI built into VS Code.
  2. Do not use source control tools.
  3. Do not download additional libraries.
  4. Ignore VS Code features that we have not introduced.

Use VS Code to edit your files, run the development server, and preview the app.

Lesson 18.2: Creating a Project

The easiest way to begin is to copy the my-first-pwa template. You can also create a completely new Vite project.

Option A: Use the my-first-pwa Template

  1. Find the my-first-pwa folder and make a copy.

    You may also download the project as a ZIP file from GitHub and unzip it.

  2. Rename the copied folder using the name of your app.

    Use lowercase letters and hyphens instead of spaces: 

    maze-game
  3. Open VS Code.

  4. Select:

    File → Open Folder
  5. Choose the folder you copied and renamed.
  6. Change the app name in the manifest file inside the public folder.
  7. Check index.html and update the app name there if necessary.

  8. Open the terminal by selecting:

    View → Terminal

  9. Type:

    npm install

    This downloads the files that the project needs in order to run.

  10. In the File Explorer, select myCode.ts and begin working.

Using the my-first-pwa template is the simplest approach because it already contains the additional files needed for our projects and installable web apps.

Option B: Create a New Vite Project

A new Vite project does not automatically include all of the PWA files found in the template.

  1. Open VS Code.

  2. Select:

    File → Open Folder
  3. Choose the folder where you want to create the new project.

  4. Open the terminal:

    View → Terminal

  5. Create a new TypeScript project:

    npm create vite@latest my-app-name -- --template vanilla-ts

    Keep the project name lowercase and use hyphens instead of spaces.

  6. After the project is created, select:

    File → Open Folder
  7. Choose the new project folder.

  8. Open the terminal again:

    View → Terminal

  9. Type:

    npm install

    This downloads the files that the new project needs in order to run.

Lesson 18.3: Running the Project

Vite includes a development server. It converts our TypeScript into JavaScript that the browser can run and sends the app files to the browser.

Open the project folder in VS Code, open the terminal, and type: 

npm run dev    # Start Vite's development server.

The terminal will display a response similar to:

VITE v8.0.16  ready in 159 ms
➜  Local:   http://localhost:5173/
➜  Network: use --host to expose
➜  press h + enter to show help

Click the Local link to view the app inside VS Code, or copy and paste the address into your browser. When VS Code opens the app in a preview window, it is still displaying the app in a browser.

Keep the terminal running while you work. Vite usually updates the page after you save your changes, but the preview can occasionally behave strangely or continue showing an older version. Refresh the preview or browser when the changes you made do not appear.

Stopping the Project

The easiest way to stop the development server is to click the trash button at the top of the bottom panel.

You can also click inside the terminal and press:

Control + C

To restart the server, type:

npm run dev

Lesson 18.4: Building and Previewing the App

While working on the app, use:

npm run dev    # Run Vite while developing the app.

When you want to create the finished version and test it, use: 

npm run build      # Create the finished app in the dist folder.
npm run preview    # Preview the finished files in dist.

After running npm run build, Vite stores the finished files in the dist folder.

Then run npm run preview and open the link shown in the terminal. This allows you to test the finished version before publishing it.

If you change the code, run npm run build again before previewing or publishing the updated version.

Lesson 18.5: Making an Installable Web App

A Progressive Web App, or PWA, is a website that can be installed and opened more like a traditional app.

The my-first-pwa template may already contain the required setup. In general, it includes:

  1. A web app manifest in the public folder.
  2. A reference to the manifest in index.html.
  3. A service worker file in the public folder.
  4. Code in main.ts that registers the service worker.

The Manifest

The manifest describes the app. It may contain:

  • the app’s name
  • its short name
  • its starting page
  • its icon
  • its display mode
  • its background and theme colors

Remember to change the app name when copying the template.

The Service Worker

A service worker runs separately from the webpage. It can help the app save files for offline use and control how those files are loaded.

The template already includes a placeholder service worker. Leave it in place. We are not building or editing the service worker when starting.

Install the App

After the PWA is hosted correctly, the browser may provide an option to install or open it as an app.

The exact button depends on the browser and operating system. Look in the address bar or browser menu for an option such as: 

Install App

Once installed, the app can open in its own window without the normal browser controls. It still uses the version of the app stored online.

Lesson 18.6: Hosting with GitHub Pages

You can upload your project to GitHub, and GitHub Pages can host the finished app for you.

Set the App’s Online Folder

GitHub Pages usually places the app inside a folder named after your GitHub project.

For example, if the project is named:

maze-game

the app may appear under:

/maze-game/

We need to tell the app to look for its files inside that folder.

In vite.config.ts, write:

import { defineConfig } from "vite";

export default defineConfig({
    base: "/maze-game/"
});

Replace maze-game with the exact name of your GitHub project.

Configure GitHub Pages

In GitHub, open your project and select:

Settings → Pages

Choose the publishing method required for the project. GitHub Pages may publish from a branch or use a GitHub Actions workflow.

After GitHub finishes publishing, it will provide a link to the app.

Installing the PWA gives this hosted website its own app icon and window. The app still loads from the version stored on GitHub Pages.
