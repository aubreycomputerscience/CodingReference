4. TREES

Lesson 4.1: Why Use a Tree?

An array is useful when we want an ordered list of items. However, arrays can become inefficient when they contain a very large amount of information.

Suppose an array contains 100,000,000 words. If we insert “kitty cat” at the beginning, every other item must move one position to the right.

Finding information can also be time consuming. If the array is not sorted, we must keep searching through the list until we find the word we want. In the worst case, that means checking all 100,000,000 items. Ouch!

If our array is sorted, then it makes an item much easier to find. But if we have to sort it, it may not be worth the trouble. With 100,000,000 items, we are talking about moving millions of values.

A tree provides another way to organize information. As each item is added, the tree places it according to a set of rules. This keeps the information sorted while providing quick lookup and insertion.

Consider adding the numbers 50, 30, 70, 20, 40, 60, and 80.

We begin with 50:

50

When we add another number, we compare it with 50.

  • Smaller numbers go to the left.
  • Larger numbers go to the right.
    50
   /  \
 30    70

We continue using the same procedure:

        50
       /  \
     30    70
    / \    / \
   20 40  60 80

Searching the Tree

Now suppose we want to check whether the tree contains 80.

  1. Compare 80 with 50. It is larger, so move right.
  2. Compare 80 with 70. It is larger, so move right.
  3. We have found 80.

We found the value in only three comparisons. In a much larger tree, each comparison eliminates a large part of the remaining data.

The tree also gives us the values in sorted order if we work through the left side, then the current value, and then the right side: 

20, 30, 40, 50, 60, 70, 80

The tree maintains this organization as items are added. We do not need to repeatedly sort the entire collection.

Lesson 4.2: A Binary Search Tree

The structure above is called a binary search tree.

The word binary means that each location can lead to no more than two additional locations:

  • one containing smaller values
  • one containing larger values

Each location is called a node. A node stores a value and references to the nodes connected beneath it.

In our example, 50 is the top node, usually called the root. 

        50
       /  \
     30    70

The nodes below another node are called its children. A node without any children is sometimes called a leaf.

This vocabulary helps us describe a tree, but the main idea is the procedure:

  1. Begin at the top.
  2. Compare the new value with the current value.
  3. Move left if it is smaller.
  4. Move right if it is larger.
  5. Continue until an empty position is found.

Searching follows the same procedure. We stop when we find the value we want or reach an empty position.

Lesson 4.3: Balanced and Unbalanced Trees

A tree works best when its values are spread reasonably evenly across its branches.

The previous example is balanced:

        50
       /  \
     30    70
    / \    / \
   20 40  60 80

We can find any value using only a few comparisons.

However, suppose we insert already sorted values:

20, 30, 40, 50, 60

The resulting tree may look like this:

20
  \
   30
     \
      40
        \
         50
           \
            60

Instead of branching, the tree has become one long chain (similar to a linked list).

To find 60, we must examine every earlier value. The tree has lost much of its advantage.

For this reason, useful tree implementations try to keep the tree balanced. Some trees rearrange their nodes as values are added. Others follow rules that allow them to build from the leaves upward. 

               1
          /         \
         2           3
       /   \       /   \
      4     5     6     7

We can think of this like building with bricks. We place the lower bricks first so that they can support the bricks above them. In the same way, a tree can build and rearrange its lower levels to maintain a balanced structure.

The exact rules depend on the kind of tree. The important idea is that the tree avoids becoming one long chain.

Lesson 4.4: Where Trees Are Used

Trees are commonly used for:

  • indexes in databases
  • files and folders on a computer

Database indexes and file systems often use balanced trees that allow each node to contain several values and connections. This helps them organize and search very large amounts of information efficiently.

Lesson 4.5: Implementing a Tree

One way to implement a tree is to create a class representing the tree and another class representing each node. 

class BinaryTree {
    topNode: TreeNode | undefined;

    insertNew(value: number) {
        // Not implemented.
    }

    delete(value: number) {
        // Not implemented.
    }

    search(value: number) {
        // Not implemented.
    }
}

class TreeNode {
    value: number;
    leftChild: TreeNode | undefined;
    rightChild: TreeNode | undefined;

    constructor(nodeValue: number) {
        this.value = nodeValue;
    }
}

The BinaryTree stores a reference to its top node and provides methods for inserting, deleting, and finding values. Each TreeNode stores a value and references to its children, which may then contain references to their own children.

A binary search tree may also be implemented using an array. This can be more efficient, but using nodes and references provides a more intuitive picture of how the tree is connected.
