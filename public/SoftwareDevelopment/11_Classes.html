Chapter 9: Classes & Obect-Oriented Programming

Lesson 9.1: Object-Oriented Programming

When an application contains 400,000 lines of code, it becomes difficult to understand and change. It is a little like writing a very long paper. We need to divide it into sections, use clear titles, and carefully organize related ideas. Otherwise, everything becomes a big mess.

In computer science, poorly organized code is sometimes called spaghetti code. Different parts of the program become tangled together, making it difficult to understand how everything works or to change one part without breaking another.

One approach to organizing a large program is called object-oriented programming. The basic idea is to divide one large program into smaller, self-contained parts. Each part manages a particular responsibility and hides details that the rest of the program does not need to understand.

Think of a toaster. We put bread into it, press a lever, and out comes toast. We do not need to understand its wires, heating elements, or electrical circuits in order to use it.

A clock works in a similar way. It displays the time and allows us to set an alarm. We can use these features without knowing how the clock works internally.

Suppose we want an alarm to go off five minutes after we press the toaster’s lever. We can describe the process using a few simple instructions:

  1. Get the toaster.
  2. Press the lever.
  3. Get the clock.
  4. Set the alarm to go off in five minutes.

The internal workings of the toaster and clock may be complicated, but we do not need to think about those details. We only need to know what each object can do and how to use it.

We can apply the same approach to programming. If we want to display a clock, we can create a self-contained piece of code that manages the time, displays it, and sets alarms. Other parts of the program can use the clock without needing to understand how it works internally.

This provides several benefits:

  • Related data and code are kept together.
  • Different tasks are separated from one another.
  • Complicated details can be hidden.
  • Code can be reused in different parts of a program.

This idea of hiding unnecessary details behind a simpler way of working with something is called abstraction.

Classes often represent recognizable things, such as characters, messages, users, clocks, or bank accounts. However, a class does not need to represent a physical object. It can also represent an abstract part of a program.

Lesson 9.2: Classes and Objects

A class groups related data and functions together. Variables inside a class are called properties, while functions inside a class are called methods.

For example, a game character has information such as a name, hit points, and maximum hit points. It can also perform tasks such as healing. 

class Character {
    name: string;
    hitPoints: number = 100;
    maxHitPoints: number = 200;

    constructor(characterName: string) {
        this.name = characterName;
    }

    heal() {
        this.hitPoints = this.maxHitPoints;
    }
}

The class describes what a character contains and what a character can do.

A particular character created from the class is called an object or an instance of the class. 

const myCharacter = new Character("Jon Snow");

The word new tells the program to create a new Character object.

The constructor runs when the object is created. It provides the object with its starting information. 

constructor(characterName: string) {
    this.name = characterName;
}

The word this refers to the current object. In this example, this.name means the name property belonging to the character being created.

We also use this when a method needs to access the object’s properties: 

heal() {
    this.hitPoints = this.maxHitPoints;
}

This method changes the character’s current hit points so that they equal the maximum hit points.

We can then call the method using the object:

myCharacter.heal();

A class allows us to create as many separate objects as we need. For example, we can create three characters from the same Character class: 

const firstCharacter = new Character("Jon Snow");
const secondCharacter = new Character("Arya Stark");
const thirdCharacter = new Character("Tyrion Lannister");

Each character follows the same class description, but it is a separate object with its own properties. We can therefore give each character a different number of hit points: 

firstCharacter.hitPoints = 50;
secondCharacter.hitPoints = 75;
thirdCharacter.hitPoints = 100;

Changing one character does not change the others. The class gives the objects the same general structure and behavior, while each object stores its own information.

Because all three objects can be used as Character objects, we can store them together and work with them in the same way: 

const myParty: Array<Character> = [
    firstCharacter,
    secondCharacter,
    thirdCharacter
];

for (const character of myParty) {
    character.heal();
}

The loop does not need separate instructions for each character. TypeScript knows that every item in the array can be used as a Character and therefore has the properties and methods required by the class.

When we create a class, TypeScript also allows us to use its name as a type: 

function healCharacter(gameCharacter: Character) {
    gameCharacter.heal();
}

The compiler checks that the value passed into this function has everything required by Character. This is one of the major benefits of using TypeScript: the compiler can catch many incorrect uses before the program runs.

However, TypeScript usually compares the public structure of objects rather than requiring that an object was created from the exact class. An unrelated object may be accepted if it has all the same required public properties and methods.

Later, we will examine this more closely when we compare classes with shape types.

Classes and JavaScript Objects

In JavaScript, an object behaves somewhat like a dictionary whose keys can lead to either data or functions.

For example, the key name may lead to a string, while the key heal may lead to a function.

This is not a complete definition of a class, but it can help us understand the syntax. A class provides an organized way to describe and create objects containing related data and behavior.

Properties and Methods

Inside a class, we do not write let or const before properties: 

class Person {
    name: string;
    greeting: string = "";
}

A method is written without the function keyword: 

class Person {
    name: string;
    greeting: string = "";

    constructor(personName: string) {
        this.name = personName;
    }

    sayHello() {
        this.greeting = "Hello, my name is " + this.name;
    }
}

We can create and use a Person object:

const person = new Person("Jon Snow");
person.sayHello();

After sayHello() runs, person.greeting contains: 

"Hello, my name is Jon Snow"

Controlling Access

By default, properties and methods can be accessed from outside the class. 

person.name = "Arya Stark";

Sometimes we want a property to be managed only by the class itself. We can mark it as private: 

class Character {
    name: string;
    private hitPoints: number = 100;

    constructor(characterName: string) {
        this.name = characterName;
    }

    heal() {
        this.hitPoints = 100;
    }
}

A private property or method can only be accessed by code inside that class. 

const character = new Character("Jon Snow");

character.hitPoints = 50; // Error: hitPoints is private.

Private and protected properties also affect how TypeScript compares class types. If two unrelated classes contain private properties, an object from one class cannot be used as the other merely because their public properties look the same.

We can also use readonly when a property should not be assigned a different value after the object is created: 

class Character {
    readonly name: string;

    constructor(characterName: string) {
        this.name = characterName;
    }
}

Now the name cannot be changed later:

const character = new Character("Jon Snow");

character.name = "Arya Stark"; // Error

Features such as private help a class protect its internal data and control how that data is changed.

Lesson 9.3: Classes and Shape Types

TypeScript uses the word type broadly. To avoid confusion, we will distinguish between classes and shape types.

A class exists when the program runs. It can create objects, contain methods, control initialization, and protect internal data.

A shape type describes what properties and methods a value must have. It is used by TypeScript while checking our code, but it disappears when TypeScript is converted into JavaScript.

We can create a shape type using a type alias:

type CharacterData = {
    name: string;
    hitPoints: number;
};

This says that CharacterData must contain a property called name whose value is a string and a property called hitPoints whose value is a number.

We can then create a value with that shape:

const characterData: CharacterData = {
    name: "Jon Snow",
    hitPoints: 100
};

The type alias does not create an object for us. It does not provide a constructor, implemented methods, or private properties. It only describes the required shape of the data.

A class can describe similar data, but it also provides the code used to create and operate its objects: 

class Character {
    name: string;
    hitPoints: number;

    constructor(characterName: string, startingHitPoints: number) {
        this.name = characterName;
        this.hitPoints = startingHitPoints;
    }

    heal() {
        this.hitPoints = 100;
    }
}

We can create a new Character using its constructor: 

const character = new Character("Jon Snow", 50);

We cannot do this with a type alias:

const character = new CharacterData(); // Error

CharacterData does not exist when the program runs. It is only used by TypeScript to check our code.

Structural Typing

TypeScript usually checks whether a value has the required public structure rather than checking which class created it. This is called structural typing.

Consider these two classes:

class Dog {
    name: string = "";
}

class Cat {
    name: string = "";
}

Both classes have the same public structure. Each contains a property called name whose value is a string.

Now consider this function:

function washDog(dog: Dog) {
    // Wash the dog.
}

TypeScript allows us to pass a Cat object into the function: 

const myCat = new Cat();

washDog(myCat); // Allowed

TypeScript is not checking whether myCat was created from the Dog class. It is checking whether the object contains the public properties and methods required by Dog.

The property names and their types must match. These two classes do not have the same public structure: 

class Dog {
    name: string = "";
}

class Cat {
    catName: string = "";
}

A Cat object cannot now be passed into washDog() because it does not contain a property called name. 

const myCat = new Cat();

washDog(myCat); // Error

Shape types work in the same general way. TypeScript checks whether the value contains the required public structure. 

type DogData = {
    name: string;
};

type CatData = {
    name: string;
};

function identifyDog(dog: DogData) {
    // Use dog.name.
}

const cat: CatData = {
    name: "Mittens"
};

identifyDog(cat); // Allowed

TypeScript allows this because cat has the shape required by DogData.

Structural typing is useful when working with data from webpages, files, or servers.

For example, a server may send us the following data: 

{
    name: "Jon Snow",
    hitPoints: 100
}

We may only need to check that the data has the expected shape. We do not always need to convert it into an object created from a class.

JavaScript began as a lightweight language for adding behavior to webpages. Languages such as Java, C#, and Swift placed a greater emphasis on classes and object-oriented organization for large applications. TypeScript later added tools for describing and checking structure, but it still builds upon JavaScript’s flexible approach.

Neither approach should be used automatically. A shape type is often useful for simple data. A class is useful when we want to provide constructors and implemented methods, control how objects are created, hide internal details, or create objects that exist as a particular class when the program runs.

Lesson 9.4: Interfaces and Interoperability

An interface describes a shared set of requirements.

For example, suppose we have several animal classes. A dog and a cat store different information and behave differently, but both can make a sound. 

interface Animal {
     makesSound(): string;
}

The interface says that anything treated as an Animal must provide a method called makesSound() that returns a string.

A class can agree to meet these requirements using implements: 

class Dog implements Animal {
     makesSound(): string {
        return "woof";
    }
}
class Cat implements Animal {
     makesSound(): string {
        return "meow";
    }
}

The Dog and Cat classes are still different classes. However, both implement the Animal interface.

This allows us to write code that works with either one:

function getAnimalSound(animal: Animal): string {
    return animal. makesSound();
}

We can pass either a dog or a cat into the function:

const dog = new Dog();
const cat = new Cat();

const dogSound = getAnimalSound(dog);
const catSound = getAnimalSound(cat);

The function does not need to know whether it received a Dog or a Cat. It only needs to know that the object follows the Animal interface and therefore provides makesSound().

We can also store different classes in the same array:

const animals: Array<Animal> = [
    new Dog(),
    new Cat(),
    new Dog()
];

for (const animal of animals) {
    const sound = animal. makesSound();
}

This ability to use different classes through the same interface is called interoperability.

The interface acts as a contract between different parts of the program. One part promises to provide particular properties or methods. Another part can then use those properties or methods without needing to know how they were implemented.

Interfaces help us separate what something can do from how it does it.

Interfaces and Shape Types

An interface is also a TypeScript shape type. Like a type alias, it describes required properties and methods and disappears when the code is converted to JavaScript. 

interface Person {
    name: string;
}

For simple data, an interface and a type alias can often describe the same shape: 

type Person = {
    name: string;
};

Interfaces are especially useful when describing requirements that classes will implement. 

interface Healable {
    heal(): void;
}

class Character implements Healable {
    hitPoints: number = 50;

    heal() {
        this.hitPoints = 100;
    }
}

The compiler checks that Character provides the method required by Healable.

The more important result is that other code can now work with any class that implements Healable. 

function restoreHealth(item: Healable) {
    item.heal();
}

This function can work with a character, animal, machine, or any other object that provides the required heal() method.

Lesson 9.5: Inheritance

Inheritance allows one class to build upon another class.

Suppose several kinds of characters share the same basic properties and methods: 

class Character {
    name: string;
    hitPoints: number = 100;

    constructor(characterName: string) {
        this.name = characterName;
    }

    heal() {
        this.hitPoints = 100;
    }
}

We can create a more specific class using extends: 

class Wizard extends Character {
    magicPoints: number = 100;

    castSpell() {
        this.magicPoints = this.magicPoints - 10;
    }
}

A Wizard inherits the properties and methods of Character. It also adds its own property and method. 

const wizard = new Wizard("Gandalf");

wizard.heal();
wizard.castSpell();

The Wizard class does not need to rewrite the name, hitPoints, or heal() code. It receives them from Character.

This describes an is-a relationship:

  • A wizard is a character.
  • A dog is an animal.
  • A car is a vehicle.

Inheritance can reduce repeated code, but it also connects classes closely together. Changes to a parent class can affect all of its subclasses.

Large inheritance hierarchies can become difficult to understand. For example, a program might contain an Animal class, a Mammal subclass, a Canine subclass, and finally a Dog subclass. As more levels are added, the organization can become more complicated than the problem it was meant to solve.

Modern programs often use interfaces when the main goal is to allow different classes to work with the same code. Interfaces provide shared requirements without forcing the classes into one inheritance hierarchy.

Another approach is composition. Composition means building a class using other objects rather than inheriting everything from one parent class.

The general principle is to use inheritance when classes truly share a close relationship and common implementation. Do not create a large class hierarchy merely because inheritance is available.

Abstract Classes

An abstract class is an incomplete class that is meant to be extended rather than used directly. 

abstract class Shape {
    abstract getArea(): number;
}

We cannot create a Shape object:

const shape = new Shape(); // Error

Instead, another class must extend Shape and provide the missing method: 

class Rectangle extends Shape {
    width: number;
    height: number;

    constructor(rectangleWidth: number, rectangleHeight: number) {
        super();

        this.width = rectangleWidth;
        this.height = rectangleHeight;
    }

    getArea(): number {
        return this.width * this.height;
    }
}

The word abstract means that Shape provides part of the description but is not complete enough to create by itself.

Abstract classes are tied to inheritance. Interfaces are usually simpler when we only need to describe shared requirements.
