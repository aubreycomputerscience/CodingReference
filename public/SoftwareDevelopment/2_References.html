Chapter 2: Understanding References

Lesson 2.1: References

A computer stores data at different locations in memory. Each location has an address that allows the computer to find the information stored there.

When we create an array, the computer places that array somewhere in memory: 

const animals = ["cat", "dog"];

We can imagine the array as a house located at a particular address. The variable animals stores the address of the house rather than everything inside it. 

Address: animals

House:
    cat
    dog

The address that leads us to the array is called a reference.

The real system is more complicated, and TypeScript does not allow us to directly see or change numerical memory addresses. Nevertheless, thinking of a reference as an address provides a useful understanding of how arrays work.

Numbers, strings, and Booleans behave differently. For now, we can think of these primitive variables as containing the value itself: 

const hitPoints = 100;
const animalName = "cat";
const isAlive = true;

Arrays and other structured types—which we will later call objects—are accessed through references.

Lesson 2.2: Why const Is Not Always Constant

Consider the following array:

const animals = ["cat", "dog"];

Because animals was declared using const, we cannot give it a different address: 

animals = ["monkey", "elephant"]; // Error

However, we can change what is stored at the existing address:

animals[0] = "tiger"; // Replace the first item in the array.

We can imagine that cat moved out of the house and tiger moved in. The address has not changed; only one of the residents has changed. 

Address: animals

Before:
    cat
    dog

After:
    tiger
    dog

When we use const with an array, the reference must remain constant. The contents of the array do not.

Lesson 2.3: Two Names for the Same Array

Suppose we write:

const firstAnimals = ["cat", "dog"];
const secondAnimals = firstAnimals;

This does not create a second array. It gives us a second name containing the same address. 

firstAnimals  \
               >  Same address: ["cat", "dog"]
secondAnimals /

Both names lead to the same array. Therefore, changing the array using either name changes the one shared array. 

secondAnimals[0] = "tiger";

// Both firstAnimals and secondAnimals now contain:
// ["tiger", "dog"]

This can be surprising because the line

const secondAnimals = firstAnimals;

may look as though it creates a second array. It actually assigns the existing array another name.

Primitive values behave differently:

let firstScore = 10;
let secondScore = firstScore;

secondScore = 20;

The first score is still 10, while the second score is now 20. Changing secondScore does not change firstScore. Each variable has its own number.

Lesson 2.4: Creating a New Array

Sometimes we want a new array containing the same items rather than another reference to the original array.

We can use the spread operator, written as three periods, to copy the items into a new array: 

const originalAnimals = ["cat", "dog"];
const copiedAnimals = [...originalAnimals];

Read ...originalAnimals as “take all the items from originalAnimals and place them here.”

Now we have two separate arrays:

originalAnimals: ["cat", "dog"]

copiedAnimals:   ["cat", "dog"]

Changing one array does not change the other.

copiedAnimals[0] = "tiger";

// originalAnimals contains ["cat", "dog"]
// copiedAnimals contains ["tiger", "dog"]

The spread operator can also combine arrays:

const plants = ["tree", "flower"];
const animals = ["cat", "dog"];

const plantsAndAnimals = [...plants, ...animals];

// plantsAndAnimals contains:
// ["tree", "flower", "cat", "dog"]

For now, remember:

  • Assigning an array to another variable creates another reference to the same array.
  • Using the spread operator creates a new array containing the same items.
