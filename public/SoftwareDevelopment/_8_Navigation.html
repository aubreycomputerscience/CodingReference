Chapter 7: Navigation

When building an app or webpage, we may need to move from one page to another. On a basic website, we can simply add links between pages. We can also move to another page through TypeScript, such as after the user submits a form.

A one-page app works differently. It may appear to move between pages, but the browser never actually loads a new webpage. Instead, the app replaces the content currently being displayed. See the chapter on HTML for an example of inserting new page content into a one-page app.

In this chapter, we will cover two approaches. First, we will use traditional page navigation and pass simple values to the next page. Then we will use hash links to make a one-page app appear to move between different pages or sections.

Lesson 7.1: Moving Between Webpages

An HTML link opens another page when the user selects it:

<a href="page2.html">Open Page 2</a>

We can also move to another page through TypeScript:

location.href = "page2.html";

This opens the new page and allows the user to return with the browser’s Back button.

Use location.replace() when the user should not return to the current page: 

location.replace("about.html"); // Replace the current page in the browser history.

Passing a Value to Another Page

When navigating through TypeScript, we can add information to the end of the webpage address: 

const personId = 42;

location.href = "details.html?id=" + personId;

The resulting address looks like this:

details.html?id=42

On the details page, we can retrieve the value from the URL: 

const params = new URLSearchParams(location.search);
const id = params.get("id");

location.search contains the part of the address beginning with the question mark. URLSearchParams separates the values so that we can retrieve them by name.

Passing Multiple Values

Use an ampersand to separate multiple values:

details.html?name=Alice&age=17

We can build the address in TypeScript:

const name = "Alice";
const age = 17;

location.href =
    "details.html?name=" + name + "&age=" + age;

Then retrieve the values on the next page:

const params = new URLSearchParams(location.search);

const name = params.get("name");
const age = params.get("age");

Values placed in the address are visible to the user. For larger information, or information that should not be placed directly in the address, save the data with localStorage, IndexedDB, or an online database and pass only an identifier.

Lesson 7.2: Navigation in a One-Page App

A hash link was originally used to move to a particular location on a long webpage: 

<a href="#arrays">Go to Arrays</a>

<h2 id="arrays">Arrays</h2>

Selecting the link moves the browser to the element whose id is "arrays".

A one-page app can also use the hash as a simple form of navigation. Instead of moving down the page, the app can detect the hash and load different content into the same HTML page: 

<a href="#arrays">Arrays</a>

Selecting the link changes the address. For example:

site.com/#arrays

The part beginning with # is called the hash. Changing the hash does not normally reload the webpage.

Our TypeScript code can detect the change and display the appropriate content: 

window.onhashchange = () => {
    const pageName = location.hash;

    if (pageName === "#arrays") {
        loadArraysPage();
    }
};

loadArraysPage() might load HTML from another file or create and display the new content directly. The browser remains on the same HTML page, while both the URL in the address bar and the content shown to the user change.

Loading the Correct Content When the App Opens

We should also load the correct content when the app first opens: 

function loadCurrentPage(): void {
    const pageName = location.hash;

    if (pageName === "#arrays") {
        loadArraysPage();
    } else {
        loadHomePage();
    }
}

window.onhashchange = loadCurrentPage;

loadCurrentPage();

This allows someone to open or bookmark a particular section of the app: 

site.com/#arrays

The browser address changes, but the app remains on the same HTML page and decides which content to display.

File Path Reference

We often identify the location of a file using a short path rather than writing its complete URL. This is convenient, but it can become confusing when files are stored in different folders. The following table provides a quick reference for the most common path forms.

Location Path
Same folder ./file
Inside a subfolder ./folder/file
Parent folder ../file
Subfolder of the parent folder ../folder/file
Two folders above ../../file
Root of the hosted website /file
Configured Vite alias @/file

./ means “start in the current folder.” Each ../ moves up one folder. A path beginning with / starts from the root of the hosted website.

Examples

src/
    myCode.ts
    tools/
        math.ts
    data/
        superheroes.ts

From myCode.ts, we can import a file from a child folder: 

import * as math from "./tools/math.ts";

From math.ts, we can move up one folder and then into the data folder: 

import * as superheroes from "../data/superheroes.ts";
