The Network and Transport Layers

The Network Layer

Architecture describes how computers divide the work. We can now look more closely at how information actually gets from one computer to another.

When two computers communicate over the internet, the information has to travel across many different networks. The job of the network layer is to move that information from one computer to another. Every computer connected to the internet has an address called an IP address. Just as every house has a mailing address, every computer has an IP address so that it can be found on the network.

As information travels, special computers called routers read the destination address and decide where to send it next. Each router uses what it knows about the network to choose the route that seems best at that moment. The next router does the same, and so on, until the information arrives.

Think About Google Maps

Think about using Google Maps while driving. You enter your destination before you leave, but the route may change as you travel. If there is heavy traffic or an accident, Google Maps may suggest a different road. The destination is fixed, but the path can change along the way.

Routers work in much the same way. The destination address stays the same, but each router decides the next step based on what it knows about the network at that moment.

Packets

When information travels across the internet, it is not usually sent all at once. Instead, it is divided into many small pieces called packets. You can think of a packet as a small container carrying part of the information from one computer to another. A large file, webpage, or video may be divided into many packets before it is sent.

The packets travel across the network and are put back together when they reach their destination. Breaking information into packets allows many different computers to share the same network efficiently. It also raises an important question: What happens if a packet gets lost or arrives out of order?

That brings us to the transport layer.

The Transport Layer

The network layer is concerned with getting information from one computer to another. The transport layer deals with another question: How should that information be delivered?

Two important transport protocols take different approaches to that problem: TCP and UDP.

TCP: Reliable Delivery

Most of the time packets arrive without a problem. But sometimes one gets lost, delayed, or arrives out of order. TCP (Transmission Control Protocol) is designed to deal with these problems.

TCP keeps track of the information being sent. It numbers the pieces so that they can be put back into the correct order. If something does not arrive, TCP can have it sent again.

The Pages of a Book

Imagine receiving the pages of a book through the mail. If every page is numbered, you can put the pages into their proper order even if they arrive mixed up. If page 47 never arrives, you can ask for page 47 again rather than requesting another copy of the entire book. TCP works in much the same way.

Because TCP checks that information arrives correctly, it is useful when accuracy and completeness matter. Webpages, email, file downloads, and online transactions commonly need this kind of reliable delivery.

TCP's basic job is straightforward: Make sure the information arrives completely and in the correct order.

UDP: Fire and Forget

UDP (User Datagram Protocol) takes a different approach. Instead of checking that everything arrives, UDP sends the information and moves on.

Imagine watching a live game. If a tiny piece of video is lost, you probably will not notice. But if the video freezes while waiting for that piece, the interruption can be much more noticeable. For things such as live video, voice calls, or many online games, keeping information moving can be more important than recovering every missing piece.

That is why UDP is sometimes described as “fire and forget.” Send it and keep going. TCP emphasizes reliable delivery. UDP provides a simpler delivery mechanism without those guarantees. Each approach is useful for different purposes.

A Note About Congestion

TCP does more than check that data arrives correctly. It also includes mechanisms that slow down transmission when the network becomes congested. UDP itself does not include that behavior. An application using UDP decides for itself how quickly to send information and may implement its own congestion-control mechanisms.

Congestion is its own topic.

Enrichment: How TCP Keeps Everything Organized

TCP uses several mechanisms to provide reliable communication. First, TCP keeps track of the sequence of data being transmitted. The receiving computer sends back acknowledgements indicating what it has received. If expected information is never acknowledged, TCP can send it again.

But TCP does not normally send one piece and then sit idle waiting for a response before sending another. That would waste a tremendous amount of time. Instead, TCP can have a group of data in transit at once. This is called a window.

As acknowledgements come back, the window moves forward and the sender continues transmitting. This mechanism is commonly described as a sliding window. The result is a useful combination: TCP can keep the network busy while still keeping track of what has arrived and retransmitting information when necessary.

Enrichment: A Simple Routing Table

How does a router decide where information should go next? It uses a routing table.

A routing table is essentially a set of directions. The router looks at the destination IP address, finds the appropriate entry in its table, and uses that entry to decide where to send the information next.

Destination Subnet Mask Next Hop Interface
192.168.1.0 255.255.255.0 Directly connected Ethernet 1
10.0.0.0 255.0.0.0 192.168.1.2 Ethernet 1
Default — 192.168.1.1 Ethernet 1

Reading the Table

Destination — The network or computer we are trying to reach.

Subnet Mask — Tells us which part of an IP address identifies the network and which part identifies a particular computer within that network. It is somewhat like distinguishing the address of an apartment building from the individual apartment number.

Next Hop — The next router to which the information should be handed.

Interface — The network connection the router uses to send the information. In other words, which connection the information is sent out through.

A real routing table can contain considerably more information, but the basic idea is simple: Look at the destination, consult the table, and determine the next step. The next router then makes its own decision, and the process continues until the information reaches its destination.
